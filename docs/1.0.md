# Pantry Specification

**Pantry** is a lightweight, self-provisioning Backend-as-a-Service designed for frontend testing. It allows developers to create dynamic API endpoints on the fly by simply sending a `POST` request, with a dedicated Admin UI to simulate real-world network conditions.

---

## 1. Core Architecture
*   **Runtime:** Node.js / Bun
*   **Framework:** Fastify (Lightweight & Schema-based)
*   **ORM:** Drizzle ORM
*   **Database:** SQLite (Better-sqlite3)
*   **Language:** TypeScript

---

## 2. Database Schema (Drizzle ORM)

```typescript
import { sqliteTable, text, integer, uniqueIndex } from 'drizzle-orm/sqlite-core';
import { sql } from 'drizzle-orm';

// Route Configuration Table
export const routeConfigs = sqliteTable('route_configs', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  path: text('path').notNull().unique(), 
  keyField: text('key_field').notNull().default('id'), 
  latency: integer('latency').notNull().default(0),
  staticCode: integer('static_code'), // HTTP status code to return
  isStatic: integer('is_static', { mode: 'boolean' }).notNull().default(false),
  staticPayload: text('static_payload'), 
}, (table) => ({
  pathIdx: uniqueIndex('path_idx').on(table.path),
}));

// Resources (JSON Data) Table
export const resources = sqliteTable('resources', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  routeId: integer('route_id')
    .notNull()
    .references(() => routeConfigs.id, { onDelete: 'cascade' }),
  data: text('data', { mode: 'json' }).notNull(), 
  createdAt: text('created_at').default(sql`CURRENT_TIMESTAMP`),
  updatedAt: text('updated_at').default(sql`CURRENT_TIMESTAMP`),
});
```

## 3. API Behavior & Endpoints

Pantry operates as a transparent proxy for dynamic data.

### 3.1. Namespaces & Routing
Pantry is strictly contained within two namespaces:
- `/admin/*`: System administration, including the UI and the management API.
- `/api/*`: **Dynamic routes**. All auto-provisioning and resource retrieval occur under this prefix.
- *Any request outside these prefixes will be ignored or return a 404.*

### 3.2. Auto-Provisioning
- **Mechanism**: If a `POST` request hits a path under `/api/` that doesn't exist, Pantry will:
    1. Create a new `route_configs` for that path.
    2. Store the payload as the first resource, using `id` as the default key.
    3. **Auto-Key**: If the `keyField` (defaulting to `id`) is missing from the payload, Pantry will automatically generate and inject it.
- **Static Routes**: Can be manually created via the Admin UI. When `isStatic` is true, Pantry returns the `staticCode` (as HTTP status) and the `staticPayload` for **any** request to that path.

### 3.2. Resource Management (CRUD)
For a provisioned path (e.g., `/api/users`):
- `GET /api/users`: Returns a list of all resources for that route.
- `GET /api/users/:id`: Returns a specific resource.
- `POST /api/users`: Adds a new resource.
- `PUT/PATCH /api/users/:id`: Updates a resource.
- `DELETE /api/users/:id`: Deletes a resource.

### 3.3. Simulation Features
Each route can have:
- **Latency**: Artificial delay in milliseconds (applied via a custom Fastify hook).
- **Static Response**: If `isStatic` is enabled, the server ignores the request method and returns the `staticCode` and `staticPayload`.

## 4. Admin UI Features (web/)

The Admin UI provides visibility and control over the vault:

- **Dashboard**: List of all active routes with quick toggles for latency and static status.
- **Route Editor**: Modify `keyField`, set `latency`, toggle `isStatic`, and edit the `staticPayload`.
- **Data Browser**: Inspect and edit the JSON data stored for each route.
- **System Maintenance**: A "Wipe All" button to reset the database and clear all dynamic routes and resources.
- **Global Logs**: Simple view of recent requests for debugging.

---

## 5. Technical Implementation Details

### 5.1. Backend (api/)
- **Fastify Plugins**:
    - `fastify-cors` for cross-origin access.
    - A custom `onSend` or `preHandler` hook to handle latency and static responses.
    - A "catch-all" handler for dynamic route provisioning, strictly scoped to `/api/*`.

### 5.2. Frontend (web/)
- **Technology**: React with Vite.
- **Styling**: Vanilla CSS (as per conventions) or a minimalist design system.
- **State Management**: Simple React Context or TanStack Query for data fetching.

---

## 6. Architecture Decisions
1. **Namespace/Prefix**: Strictly divided into `/admin/*` (management) and `/api/*` (dynamic). All other paths are blocked.
2. **Persistence**: SQLite (Persistent). A "Wipe" feature is provided for resetting the test environment.
3. **Key Resolution**: Defaulting to `id` for version 1.0.
